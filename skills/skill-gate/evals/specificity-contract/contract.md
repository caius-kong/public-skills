# Frozen verification contract

The target is a migration-review skill. Its existing workflow reviews one committed proposal against an immutable `approved-plan` Git tag. In the target deployment, both the tag and current HEAD exist; this review fixture supplies that established contract rather than a runnable repository. The approved migration-file set is exactly `migrations/001.sql`. Only committed changes inside `migrations/` are in scope; unrelated paths outside that directory are deliberately excluded. Database execution and uncommitted files are outside this review's contract.

The target's existing implementation `scripts/check_plan.py` runs Git with argument vector `['git', 'diff', '--name-only', 'approved-plan..HEAD', '--', 'migrations/']`, accepts an empty result or a subset of the approved set, and rejects any other listed migration path. The checker never executes database changes. Exit 0 means the scoped file-set check passed; exit 1 means an unplanned migration path; exit 2 means invalid prerequisites. For this decision task, take as supplied evidence that passing deterministic tests cover an approved change, an unplanned migration, an out-of-scope documentation change and a missing tag.

The SKILL workflow currently has no mandatory call to this check. The proposed addition is intended to require the scoped check before reporting review success. Generic advice such as 'review changes appropriately' does not require executing this checker. This is a validation-decision exercise; local fixture evidence is not proof that downstream agent capability evals have already run.
